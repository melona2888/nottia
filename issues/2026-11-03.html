01 Icebreaker 선정 이유: 웹 콘텐츠 선택권

웹사이트의 AI 학습 선호, 제공자마다 따로 쓰는 부담을 줄인다

OpenAI는 웹사이트 운영자가 robots.txt에 적는 공통 AI 학습 선호 신호를 존중하겠다고 발표했습니다. 여러 제공자에게 같은 의사를 전하는 길을 만들려는 움직임이며, 실제 구현은 아직 예정 단계입니다.

제공자마다 규칙을 쓰던 부담

지금은 운영자가 크롤러별로 별도 규칙을 관리합니다. 공통 신호는 참여하는 여러 제공자에게 같은 학습 선호를 전달하도록 설계됐습니다.

robots.txt에 한 가지 신호

웹사이트가 이미 쓰는 파일에서 기초 생성형 AI 학습에 대한 선택을 표현합니다. 모든 웹 콘텐츠 이용을 통제하는 완성된 표준으로 받아들이면 안 됩니다.

기존 크롤러 통제는 유지

OpenAI는 기존 robots.txt 크롤러별 설정도 계속 존중한다고 밝혔습니다. 새 신호가 현재의 개별 설정을 곧바로 대체하지는 않습니다.

구현은 앞으로 몇 달

OpenAI는 향후 몇 달 안에 신호를 구현하고 세부사항을 다시 알릴 계획입니다. 현재 모든 크롤링에 이미 적용된 기능으로 소개할 단계는 아닙니다.

02 Main 선정 이유: 장기 작업과 보안 모델

Gemini 4 Carbon, 오래 걸리는 코딩과 보안 작업을 겨냥하다

Google은 Gemini 4 Carbon을 장기 엔지니어링과 사이버 방어 능력에 초점을 둔 차기 프런티어 모델로 발표했습니다. 작업을 오래 이어가며 취약점을 찾고 수정하는 성능을 강조하지만, 일반 사용자가 바로 고를 수 있는 모델은 아닙니다.

며칠씩 이어지는 작업 목표

Google은 대형 코드베이스의 까다로운 버그를 찾아 고치는 내부 장기 작업 사례를 소개했습니다. 이는 공급사 내부 사례이며 모든 프로젝트의 완주 시간을 보장하지 않습니다.

찾기·검증·수정으로 나눈 평가

취약점 발견, 공격 가능성 확인, 원인 수정의 별도 평가 결과를 제시했습니다. 공개 수치는 Google 발표 기준이므로 실제 저장소의 보안 품질은 따로 확인해야 합니다.

먼저 신뢰된 방어 담당자에게

초기 접근은 일부 사이버 방어 담당자에게 한정되며, 추가 신뢰 파트너는 Fairwind Program을 통해 참여합니다. 개발자·기업·소비자 제품 제공은 이후로 예고됐습니다.

능력만큼 배포 경계도 중요

강한 보안 능력을 내세우면서 사전 테스트와 단계적 제공을 택했습니다. 멘토링 프로젝트에서도 자동 수정의 범위와 사람의 검토 지점을 분리할 이유를 보여줍니다.

02 Main 선정 이유: 이상 행동 탐지와 개입

프런티어 모델 감시, 한 번의 판정이 아니라 여러 층으로 본다

OpenAI는 프런티어 모델이 훈련·평가·도구 사용 중 의도와 다른 행동을 보이는지 감시하는 내부 체계를 공개했습니다. 가벼운 1차 탐지 뒤 더 깊은 검토와 사람의 조사로 넘기는 다층 구조가 핵심입니다.

훈련·평가·도구 사용까지 본다

강화학습 실행과 평가, 도구를 쓰는 내부 작업을 감시 범위에 포함합니다. 외부 배포는 제품 표면에 따라 수정된 체계를 적용하므로 내부와 같은 범위라고 단정할 수 없습니다.

가벼운 선별 뒤 깊은 검토

일반 작업은 내부 활성 패턴을 보는 탐지기에서 시작해 모델 기반 검토, 보안 조사, 정렬 연구 검토로 이어집니다. 프런티어 강화학습과 내부 Codex 트래픽은 첫 단계를 건너뛰고 모델 검토부터 시작합니다.

정상 표본도 다시 본다

첫 단계에서 경고하지 않은 트래픽의 일부도 무작위로 다음 검토에 보냅니다. 새로운 유형을 놓치는지 확인하려는 감사이며, 탐지기 하나의 정확도만 믿지 않는 방식입니다.

감지는 안전 보장의 동의어가 아님

감시는 놓치거나 정상 행동을 경고할 수 있고, 외부 제품에서는 개인정보와 대화 맥락 제약도 생깁니다. 프로젝트에서는 권한 제한과 사람 승인 같은 별도 통제를 함께 둬야 합니다.

02 Main 선정 이유: 화면 행동 승인 경계

Gemini Computer Use 정식 제공, 화면 조작에 사람 확인 정책을 붙인다

Google Cloud의 Computer use 도구가 10월 30일 정식 제공 상태로 바뀌었습니다. 에이전트가 화면에서 행동하는 기능을 제품에 붙일 때, 어떤 작업을 사람에게 확인받을지 설정하는 운영 경계도 함께 제시했습니다.

Computer use 도구 GA

Gemini API의 Interactions와 GenerateContent 두 API에서 정식 제공됩니다. 연구 미리보기를 넘어서 애플리케이션 통합 경로가 분명해졌습니다.

민감한 행동은 확인 요청

Cloud 릴리스 노트는 금융 거래나 데이터 수정 같은 행동의 확인 정책을 개발자가 조정할 수 있다고 설명합니다. 화면 조작 성공과 행동 승인 여부는 별개로 다뤄야 합니다.

관리자 보호 규칙 우선

조직 관리자는 제약 설정으로 공통 안전 규칙을 강제할 수 있습니다. 개별 앱의 설정만으로 모든 확인 단계를 풀 수 있는 구조는 아닙니다.

완료 증거까지 남겨야

화면 자동화 프로젝트는 클릭 기록뿐 아니라 최종 화면과 변경된 데이터의 확인이 필요합니다. 이는 제품 발표에서 도출한 프로젝트 적용 판단입니다.

02 Main 선정 이유: AI 행동 원칙 공개

OpenAI Model Spec 개정, 맥락과 부작용을 판단 기준에 올리다

OpenAI는 모델이 낯선 상황에서 사용자 의도와 감독을 어떻게 해석해야 하는지 공개 Model Spec을 다시 구성했습니다. 명령을 그대로 따르는 문제뿐 아니라 인간의 선택권과 외부 부작용을 고려하는 기준을 더 선명하게 썼습니다.

다섯 가치로 재구성

사용자 의도에 대한 충실성, 피해 최소화, 정직성과 투명성, 인간의 주도권, 배려를 중심에 두었습니다. 개발자와 사용자의 지시도 이 경계 안에서 해석합니다.

대화·기억·개인화의 맥락

사용자의 선호를 읽을 때 대화와 기억을 어떻게 활용할지 설명을 늘렸습니다. 과거 맥락만으로 현재의 새로운 의도를 단정하지 않도록 보는 문제와 이어집니다.

외부 부작용을 알리고 통제

모델의 행동이 다른 사람이나 시스템에 미칠 결과를 고려하고 사용자에게 전달하는 원칙을 보강했습니다. 도구를 쓰는 에이전트의 승인 지점을 설계할 때 참고할 기준입니다.

문서가 곧 실현은 아님

OpenAI는 현재 모델 행동이 개정된 Spec을 완전히 반영하지는 않는다고 명시했습니다. 공개 원칙과 실제 제품의 행동은 따로 평가해야 합니다.

03 Dev 선정 이유: 작업 세션의 연속성

Copilot 작업, 웹에서 시작해 휴대전화와 IDE에서 이어간다

GitHub는 Copilot의 클라우드 세션을 웹, 모바일, 앱, CLI, VS Code와 대화 도구에서 이어 쓰는 흐름을 공개했습니다. 같은 작업의 맥락을 다시 붙여 넣지 않아도 되는 대신, 세션이 실행되는 환경과 비용을 함께 봐야 합니다.

기기를 바꿔도 같은 세션

GitHub 웹·모바일에서 작업을 시작해 Copilot 앱, CLI, VS Code에서 이어갈 수 있습니다. Slack과 Teams의 대화에서도 작업을 요청하는 경로가 연결됩니다.

클라우드 샌드박스의 재개

기본 세션은 로컬 컴퓨터와 분리된 GitHub 관리 환경에서 실행됩니다. 저장된 스냅샷을 이용해 뒤에 다른 화면에서 같은 세션을 재개할 수 있습니다.

유료 Copilot 플랜에 제공

연결된 클라우드 경험과 샌드박스는 유료 플랜에서 일반 제공 상태입니다. 조직 정책과 저장소 접근 권한은 세션에서 볼 수 있는 범위를 제한합니다.

샌드박스 사용량은 공동 풀

2026년 11월부터 클라우드 샌드박스 사용량이 Actions와 공유하는 컴퓨트 할당량에서 차감됩니다. 반복 자동화에서는 세션 시간과 비용도 살펴야 합니다.

03 Dev 선정 이유: 작업별 모델 라우팅

Copilot Fusion, 작업마다 모델과 실행 흐름을 고른다

GitHub는 사용자가 매번 하나의 모델을 고르는 대신 Copilot이 작업에 맞는 모델과 조합 방식을 선택하는 Fusion을 정식 제공했습니다. 사용자는 노력 수준을 고르고, 관리자는 조직에서 허용할 모델과 기본값을 정합니다.

모델 대신 노력 수준을 선택

Standard, High, Max 가운데 작업에 쓸 노력 수준을 고르면 Fusion이 사용할 모델을 정합니다. 강한 모델 하나를 모든 작업에 고정하는 방식과 다릅니다.

단일·단계 상승·비평 흐름

한 모델이 바로 풀거나, 1차 답을 검사해 더 강한 모델로 넘기거나, 다른 모델이 초안을 비평한 뒤 수정하는 세 흐름을 작업에 따라 사용합니다.

조직이 후보 모델을 제한

Fusion은 기업·조직 정책에서 허용된 모델만 사용합니다. 관리자는 후보별 허용 상태와 기본 노력 수준을 따로 설정할 수 있습니다.

벤치마크와 비용은 함께 읽기

GitHub가 제시한 성능·토큰 수치는 공급사 평가이며, 사용한 각 모델은 표준 요율로 청구됩니다. 실제 저장소에서는 품질뿐 아니라 선택 경로와 비용도 기록해야 합니다.

스캔된 미국 재무부 문서 1,435개와 질문 70개로 에이전트의 숫자 답변을 평가합니다. Dropbox MCP 검색 뒤 OCR이나 도구로 읽는 과정에서 틀린 수치가 나오는지 봐야 합니다. arXiv

Pre-Crime: 유출 직전 신호를 잡는다

통제된 다중 에이전트 대화에서 비밀을 누설할 호출을 사전에 탐지하는 방법입니다. 허용된 공개도 경고하고 정상 작업까지 멈출 수 있어 실제 차단 정책으로 쓰기 전 구분이 필요합니다. arXiv

CIRCE: 풀기 전 제약 구조로 난도 예측

문제의 변수와 제약 관계를 그래프로 바꿔 모델이 맞힐 가능성을 추정합니다. 7개 추론 벤치마크와 4개 모델의 결과이므로 모든 실무 요청의 라우팅 성능으로 일반화하면 안 됩니다. arXiv

Careful Searchers: 언제 검색할지 평가

기억으로 답할 질문과 최신 사실을 검색해야 할 질문 400개로 검색 결정을 측정합니다. 제품의 도구 실행 행동을 본 결과이며 모델의 내면적 자기인식을 증명하지는 않습니다. arXiv

GAFL: 자기 보고를 다시 확인한다

협업 학습에서 참여자가 낸 거버넌스 증거를 독립적으로 재검사하고 기록합니다. 10개 참여자의 한 데이터셋 실험에서 허위 증거 탐지가 좋아졌지만 처리 비용과 공정성 기준의 오탐 부담이 남습니다. arXiv
