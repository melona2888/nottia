Nottia Weekly Newsletter / 11호 2026.08.05 - 2026.08.11

AI가 더 강해질수록, 통제와 선택이 제품이 된 주

말로 파일을 읽는 ChatGPT, 무료 이용자까지 넓어진 GPT-5.6, 사이버 전용 모델과 강화된 통제, 사용 패턴으로 모델을 고르는 라우터까지. 이번 주는 성능보다 운영 경계가 더 선명해졌습니다.

This Week in 4 Lines

  1. ChatGPT Voice가 파일과 Projects를 받아, 말로 묻는 대화가 실제 작업 맥락 안으로 들어왔습니다.
  2. GPT-5.6 Sol은 답변 집중도와 사실 신뢰성을 다듬고, Luna는 무료 이용자의 기본 모델로 확대됩니다.
  3. OpenAI는 GPT-5.6-Cyber와 Astra를 통해 강한 사이버 능력에는 더 엄격한 접근·감사·샌드박스가 필요하다고 선언했습니다.
  4. OpenRouter와 GitHub는 모델 선택, 에이전트 병렬 작업, MCP 서버 허용 범위를 제품 기능으로 끌어올렸습니다.

Editorial Note

이번 주의 핵심은 새 모델 이름이 아닙니다. 모델이 파일, 도구, 저장소, 보안 환경에 연결되자 제품의 차별점이 “얼마나 똑똑한가”에서 “누가 무엇을 허용하고, 어떤 모델을 고르며, 실행을 어떻게 검증하는가”로 이동했습니다.

01 Icebreaker 선정 이유: 음성과 문서의 결합

ChatGPT Voice, 말로 파일을 읽고 프로젝트 맥락까지 이어간다

8월 7일부터 GPT-Live 기반 ChatGPT Voice가 파일 업로드와 Projects를 지원합니다. 음성 대화가 가벼운 질문을 넘어 문서와 최근 작업 맥락을 함께 보는 입력 방식으로 확장됐습니다.

말하면서 파일 업로드

음성 대화 중 파일을 올리고 내용을 분석하거나 질문할 수 있습니다. 문서를 먼저 읽고 채팅창으로 돌아오는 단계를 줄입니다.

Projects 안에서도 음성

최근 프로젝트 대화, 연결된 출처, 프로젝트 지침을 음성 대화가 참고합니다. 일회성 질문보다 이어지는 업무에 가깝습니다.

GPT-Live의 다음 사용면

동시에 듣고 말하는 자연스러운 대화 위에 문서 맥락이 붙었습니다. 음성 인터페이스가 실제 작업 화면으로 들어오는 변화입니다.

파일 정확도는 다시 확인

음성이 입력 방식을 편하게 만들 뿐, 문서 해석의 오류 가능성을 없애지는 않습니다. 숫자와 결론은 원문과 대조해야 합니다.

OpenAI ChatGPT Release Notes
02 Main 선정 이유: 접근성의 구조 변화

GPT-5.6, 유료에는 사고량 조절을, 무료에는 기본 접근을

OpenAI는 8월 6일 ChatGPT용 GPT-5.6 Sol을 업데이트하고, 무료 이용자의 기본 모델을 GPT-5.6 Luna로 바꾸겠다고 발표했습니다. 같은 모델군을 요금제와 작업 난도에 따라 나누는 방식이 더 분명해졌습니다.

답변은 더 짧고 집중되게

Plus와 Pro의 Sol은 사실 신뢰성, 직접적인 답변, 불필요한 형식 축소를 목표로 조정됐습니다.

사고량 슬라이더

같은 Sol 모델에서 응답에 얼마나 많은 사고를 쓸지 고릅니다. 모델 교체보다 작업별 추론 예산 조절에 가깝습니다.

무료 기본은 Luna

Free와 Go 이용자는 Luna를 기본으로 쓰며, 텍스트 채팅은 남용 방지 조건 아래 무제한으로 확대될 예정입니다.

Work와 Codex는 별도

이번 변경은 ChatGPT의 채팅 경험에만 적용됩니다. Work와 Codex의 모델 동작이 함께 바뀐 것으로 해석하면 안 됩니다.

OpenAI 발표
02 Main 선정 이유: 고위험 모델의 접근 설계

GPT-5.6-Cyber, 강한 보안 능력을 일반 API가 아닌 승인제 환경으로

OpenAI는 Daybreak를 Blue와 Red로 나누고, 사이버 보안 특화 모델 GPT-5.6-Cyber를 Red 승인 사용자에게 제공한다고 발표했습니다. 능력 공개와 접근 제한을 한 제품 설계 안에 묶은 사례입니다.

Blue는 방어 업무의 출발점

GPT-5.6 Sol을 취약점 탐색, 보안 코드 리뷰, 악성코드 분석, 사고 대응에 쓰도록 방어 작업용 제한을 조정합니다.

Red는 고위험 연구용

GPT-5.6-Cyber는 익스플로잇 검증과 고급 보안 테스트처럼 이중용도 위험이 큰 작업을 승인된 환경에서 다룹니다.

완료율 95%, 내부 평가 기준

OpenAI의 Advanced Cybersecurity Completion Rate에서 95.0%를 기록했습니다. 외부 독립 평가가 아니라 내부 지표라는 점이 중요합니다.

계정·실행을 함께 통제

신원 확인, 모니터링, 법적 확인, 하드웨어 보안키, 샌드박스와 auto-review를 결합합니다. 모델 권한만 켜는 방식이 아닙니다.

OpenAI Daybreak 발표
02 Main 선정 이유: 능력 공개와 배포 보류

Astra, ‘치명적 사이버 능력’을 배제하지 못해 통제를 먼저 강화

OpenAI는 8월 7일 차기 모델 Astra의 내부 평가에서 Preparedness Framework의 Critical 사이버 능력을 배제할 수 없다고 밝혔습니다. 아직 출시 발표가 아니라, 배포 전 안전 기준을 올린 상태입니다.

Critical은 무인 공격 능력

강화된 실제 시스템에서 제로데이 공격을 만들거나, 높은 수준의 목표만으로 종단간 공격을 수행할 수 있는 수준을 뜻합니다.

출시가 아니라 예비 평가

Astra는 예정 모델이며 평가는 진행 중입니다. “Critical 확정”이나 “곧 공개”로 단정할 근거는 없습니다.

조건 미달 활동은 중단

강화된 보안 통제를 충족하지 못한 내부 활동을 일시 중지하고, 격리 환경과 제한된 네트워크·도구 접근을 적용했습니다.

모델만이 아니라 실행을 감시

에이전트 행동과 위험 신호를 보편적으로 모니터링하고, 필요하면 작업을 검토·중단하는 운영 계층을 강화했습니다.

02 Main 선정 이유: 모델 선택의 자동화

OpenRouter Auto, 벤치마크 한 장 대신 실제 사용 지출로 모델을 고른다

OpenRouter는 8월 10일 Auto router를 개편했습니다. 지난 7일 동안 작업 유형별로 어떤 모델에 사용자가 실제 비용을 썼는지 집계해, 비용 등급에 맞는 모델과 대체 경로를 고릅니다.

주간 55조 토큰의 선택 신호

OpenRouter는 주간 사용량의 지출 패턴을 라우팅 근거로 씁니다. 새 모델이 등장해 사용이 이동하면 며칠 안에 반영될 수 있습니다.

약 30개 작업 유형

코드 디버깅, 에이전트 계획, 조사 보고서처럼 프롬프트를 세분화한 뒤 해당 유형에서 많이 선택된 모델을 찾습니다.

비용 등급을 직접 지정

cost_tier를 low부터 max까지 고를 수 있습니다. 모델명 대신 허용 비용과 품질 목표를 입력하는 방식입니다.

시장 선택은 품질 보증이 아님

집단 사용 패턴은 최신성이 있지만 편향도 담습니다. OpenRouter 자체 벤치마크 결과와 실제 업무 검증을 함께 봐야 합니다.

03 Dev 선정 이유: 오픈웨이트 모델의 유통

Kimi K3, 이제 GitHub Copilot의 모델 선택지로

GitHub는 8월 6일 Kimi K3를 Copilot에 일반 제공하기 시작했습니다. 오픈웨이트 모델이 별도 로컬 구축 없이 상용 개발도구의 모델 선택기에 들어온 사례입니다.

VS Code부터 모바일까지

Copilot 앱, CLI, cloud agent, github.com, 모바일과 주요 IDE에 순차 배포됩니다. 계정마다 노출 시점은 다를 수 있습니다.

Fireworks AI에서 호스팅

모델이 오픈웨이트라는 사실과 실행 환경이 로컬이라는 뜻은 다릅니다. Copilot에서는 GitHub가 Fireworks AI를 통해 제공합니다.

공급자 가격으로 과금

사용량 기반 과금에서 입력 100만 토큰당 3달러, 출력 15달러, 캐시 입력 0.30달러가 안내됐습니다.

기업은 기본 비활성

Business와 Enterprise는 관리자가 정책을 켜야 합니다. 보안·규정·데이터 거버넌스 검토가 먼저라는 의미입니다.

03 Dev 선정 이유: 병렬 작업의 일상화

Copilot, 에이전트 한 줄 대신 여러 세션과 격리 작업공간으로

8월 7일 Copilot 주간 업데이트는 앱, CLI, VS Code 전반에 병렬 질문, 동시 세션, 격리된 worktree, 변경 되감기를 추가했습니다. 에이전트 작업이 한 대화에서 여러 작업면으로 분화하고 있습니다.

주 작업을 멈추지 않는 옆 질문

앱의 /side와 VS Code의 /btw는 주 세션 맥락을 공유하면서 별도 질문을 처리합니다.

CLI에서 격리 worktree

실험적 /worktree 명령은 별도 작업공간과 대화를 열어 기존 변경을 건드리지 않고 탐색하게 합니다.

Git 없이도 되감기

/rewind는 Copilot이 바꾼 대화와 파일 상태를 복원하면서 이후 사람이 만든 변경은 보존하도록 설계됐습니다.

웹 요소에 직접 피드백

VS Code Agent 창에서 페이지 요소를 고르고 여러 코멘트를 붙여 시각 피드백을 구체적인 수정 요청으로 보냅니다.

GitHub Copilot 주간 릴리스
03 Dev 선정 이유: MCP 공급망 통제

GitHub Copilot, 기업이 허용한 MCP 서버만 실행하게 한다

GitHub는 기업 관리 설정에 MCP 서버 허용·차단 목록을 일반 제공했습니다. 개발자가 연결하는 도구의 범위를 중앙 정책으로 제한하는 기능입니다.

URL과 명령으로 식별

원격 서버 URL이나 로컬 stdio 명령과 인자를 기준으로 허용 여부를 판단합니다. 표시 이름은 보안 기준으로 쓰지 않습니다.

잘못된 정책은 차단

설정을 해석할 수 없으면 허용하지 않는 fail-closed 방식입니다. 여러 정책 계층이 있으면 모두 통과해야 합니다.

앱·CLI·VS Code 적용

현재 GitHub Copilot 앱, Copilot CLI, VS Code에서 집행됩니다. 모든 MCP 클라이언트에 자동 적용되는 범용 표준은 아닙니다.

도구 연결도 공급망

MCP는 에이전트의 권한을 넓히므로, 모델 정책만큼 서버 출처와 실행 명령을 관리해야 한다는 신호입니다.

04 Research 선정 이유: 에이전트 신뢰성의 다섯 축

이번 주 연구: 스킬, 기억, 통계, 감사, 실행 증명

이번 주 논문들은 에이전트의 성능을 높이는 것보다 실패를 진단하고 낡은 지식을 지우며, 실행 흔적과 권한 준수를 검증하는 방법에 집중했습니다. 아래 수치는 모두 논문 저자 보고이며 독립 재현 전 단계입니다.

SkillProx · 나쁜 스킬은 되돌리고 삭제

실패 진단 뒤 같은 작업으로 수정 효과를 다시 확인하고, 기여도가 낮은 지식 단위는 제거합니다. 저자들은 강한 기준선보다 평균 정확도 3.0%p 향상을 보고했습니다.

TEPA · 오래된 기억은 폐기 가능하게

새 증거가 기존 기억과 충돌하면 활성 기억에서 취소하되 감사 기록은 남깁니다. 기억을 계속 추가하는 것만으로는 변화한 세계를 따라가지 못한다는 지적입니다.

Fisher-R1 · 실행 성공과 통계 타당성 분리

코드가 정상 실행돼도 잘못된 검정과 p값으로 결론을 틀릴 수 있습니다. P-Bench 425개 과제로 통계적 추론 자체를 평가합니다.

A²E · 모델과 하네스를 함께 감사

표준화된 실행 추적을 모아 정확도뿐 아니라 도구 사용, 계획, 오류 복구를 비교합니다. 모든 작업에 항상 이기는 조합은 없었다고 보고합니다.

NiyamAI · 허용된 실행을 암호학적으로 증명

도구와 제약을 Intent Contract로 잠그고, 실행 전 zk-SNARK 증명을 검증합니다. 승인 동작마다 약 2.26초의 증명 비용이 추가되는 실험적 접근입니다.
