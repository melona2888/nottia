데이터 원문을 보지 않는 안전 감시, 화면을 직접 다루는 Claude, 유료 API를 결제하는 에이전트, Slack에서 PR을 만드는 Copilot까지. 이번 주 AI는 더 강한 실행력만큼 더 분명한 운영 경계를 요구했습니다.

This Week in 4 Lines

  1. Claude Academy는 기능 암기보다 무엇을 AI에 맡기고 사람이 어디를 검토할지 판단하는 AI 문해력을 강조했습니다.
  2. OpenAI는 데이터 원문을 보지 않는 장기 위험 감시와 사이버 임계 역량 앞에서의 훈련 페이싱을 공개했습니다.
  3. AWS는 에이전트가 유료 API와 콘텐츠를 직접 결제하도록 하되, 세션별 한도와 감사 로그를 인프라에서 강제하기 시작했습니다.

Editorial Note

이번 주의 핵심은 더 똑똑한 모델 하나가 아니라 AI가 실제 조직 안에서 오래 일하기 위한 주변 장치입니다. 기억과 권한, 결제와 감사, 사람의 승인과 검증이 함께 설계되지 않으면 에이전트의 자율성은 생산성보다 운영 위험을 먼저 키울 수 있습니다.

01 Icebreaker 선정 이유: 누구나 필요한 AI 문해력

Claude Academy, 프롬프트 기술보다 ‘무엇을 맡길지’부터 가르친다

Anthropic은 8월 20일 Claude Academy의 교육 원칙과 이용 경로를 공개했습니다. 특정 기능을 빨리 익히는 법보다 AI가 틀릴 수 있는 지점, 사람에게 남겨야 할 판단, 결과를 검증하는 강도를 중심에 둔 것이 특징입니다.

기능보다 판단 습관

모델 기능은 빠르게 바뀌므로 특정 프롬프트 공식보다 위임 범위와 검증 수준을 판단하는 습관을 오래 가는 역량으로 봅니다.

중요할수록 더 강하게 검증

법률·재무·고객 문서처럼 결과의 비용이 큰 작업은 AI가 만든 초안과 근거를 더 엄격히 확인하라는 원칙입니다.

사람의 기술을 남긴다

반복 작업은 AI에 맡기더라도 스스로 중요하게 여기는 능력까지 전부 대체해 기술이 약해지지 않도록 경계를 정하게 합니다.

지금 바로 공개 학습

과정과 튜토리얼은 Claude Academy와 Claude 프로필의 Learn more에서 접근할 수 있습니다. 내용은 Claude 중심이지만 일부 과정은 모델 중립적으로 구성됐습니다.

02 Main 선정 이유: 기업 데이터 보호와 안전

ZDR와 안전 감시를 동시에 하려는 OpenAI의 새 실험

OpenAI는 Zero Data Retention 고객용으로 Private Safety Processing을 미리 공개했습니다. 요청과 응답을 OpenAI 직원이 볼 수 없게 유지하면서도, 여러 상호작용에 걸친 위험 패턴을 자동 시스템이 제한된 신호로 감지하는 구조입니다.

대화 저장 없이 보는 위험 흐름

기존 ZDR 안전 시스템은 개별 상호작용 중심이었습니다. 새 프리뷰는 여러 요청에 걸친 반복 탐색, 우회 시도, 긴 에이전트 작업의 이탈을 보려는 방향입니다.

고객 인프라 또는 고객 키 암호화

콘텐츠는 고객이 통제하는 인프라에 남거나, OpenAI 저장소를 쓰더라도 고객 키로 암호화됩니다. OpenAI 직원은 키를 갖지 않는다고 설명합니다.

OpenAI에는 제한된 안전 신호만

위험이 감지되면 활동 유형 같은 좁은 신호가 전달됩니다. 원문 프롬프트와 응답을 자동으로 열람한다는 의미는 아닙니다.

9월 백서 전까지는 프리뷰

현재는 초기 고객 테스트 단계입니다. 규제 산업에서 쓸 수 있는지 판단하려면 기술 백서, 감사 가능성, 예외 처리 범위를 더 확인해야 합니다.

02 Main 선정 이유: 프런티어 모델 안전 운영

사이버 임계 역량 앞에서, 모델 훈련 속도도 안전 변수로 바뀌었다

OpenAI는 내부 모델 Astra가 Preparedness Framework의 Critical cybersecurity capability 문턱에 도달할 수 있다는 예비 증거 때문에 일부 프런티어 RL 훈련을 늦췄다고 밝혔습니다. 성능 경쟁보다 연구 환경 보안과 모니터링을 먼저 끌어올리겠다는 운영 신호입니다.

프런티어 RL 2주 정지

배포 의도 모델의 최신 RL 훈련 일부를 멈추고, 연구 환경 하드닝과 레드팀을 확대했습니다. 가장 큰 RL 실행은 더 작은 실험과 평가가 끝날 때까지 보류됩니다.

코드 실행 연구 환경 격리

도구와 인터넷 접근이 있는 연구 워크로드에는 더 강한 샌드박스와 네트워크 격리가 적용됩니다. 모델이 코드와 외부 시스템을 다룰수록 연구실 자체가 공격 표면이 됩니다.

30분 안에 경보 판단

모니터링 시스템은 우려 활동을 올린 뒤 30분 안에 판단하는 흐름을 목표로 합니다. 오탐 여부를 결론내지 못하면 활동을 멈추는 절차를 둡니다.

추론 컴퓨트 약 20% 오버헤드

OpenAI는 현재 모니터링 비용을 대상 추론 컴퓨트의 약 20%로 추정합니다. 안전 운영이 모델 비용 구조의 별도 항목으로 드러난 셈입니다.

OpenAI 사이버 역량 운영 공지
02 Main 선정 이유: 에이전트 결제의 상용화

AWS AgentCore payments, 에이전트가 유료 API와 콘텐츠를 직접 결제한다

AWS는 8월 18일 AgentCore payments를 일반 제공으로 전환했습니다. 에이전트가 작업 도중 유료 MCP·API·콘텐츠에 접근하고 결제하되, 지갑 비밀정보와 지출 상한은 인프라가 통제합니다.

유료 도구를 작업 중 구매

에이전트가 402 Payment Required 응답을 만나면 흐름을 끊지 않고 유료 API, 모델 추론, 콘텐츠 접근 비용을 처리할 수 있습니다.

지갑 비밀정보는 에이전트 밖에

Coinbase와 Stripe Privy 지갑을 지원하고, 원본 자격증명은 Secrets Manager에 둡니다. 에이전트에는 짧게 유효한 토큰만 전달됩니다.

세션별 금액·시간 상한

결제 세션에는 최대 지출액과 만료 시간을 설정합니다. 재시도나 오해로 예산을 넘기려는 요청은 인프라 계층에서 결정적으로 거부됩니다.

감사 로그가 필수 기능

CloudWatch와 AgentCore Observability에 거래 로그·성공률·평균 금액을 남깁니다. 자율 결제는 편의보다 예산과 감사 가능성이 먼저입니다.

02 Main 선정 이유: 장기 기억 에이전트 연구

Google DeepMind, 게임을 장기 기억 에이전트의 실험실로 다시 꺼냈다

Google DeepMind는 Fenris Creations와 EVE 세계를 활용한 게임 AI 연구 협력을 설명했습니다. 게임을 점수 최적화 문제가 아니라 지속적으로 변하고, 사회적이고, 오래 기억해야 하는 세계로 보고 에이전트 연구를 확장하는 흐름입니다.

점수보다 세계 이해

DeepMind는 SIMA 계열처럼 화면을 보고 자연어 지시를 이해하며 키보드와 마우스로 행동하는 일반 에이전트를 연구합니다. 게임 코드 접근 없이 사람 같은 조작을 목표로 합니다.

EVE는 오래 변하는 실험장

EVE Online과 EVE Frontier는 경제, 협력, 경쟁, 규칙 변화가 섞인 지속 세계입니다. 며칠이 아니라 몇 주, 몇 달을 기억하고 계획하는 능력을 시험하기 좋습니다.

게임 QA도 에이전트 과제

개발 중 게임이 계속 바뀔 때 일반 에이전트가 회귀 테스트와 탐색을 맡을 수 있습니다. 실제 제품 적용은 안전한 오프라인 샌드박스와 성숙도 확인 이후로 제한됩니다.

현실 문제 전이의 전 단계

게임은 위험을 낮춘 복잡 세계입니다. 다만 플레이어 가치와 재미를 목표로 하는 연구라, 업무 자동화 성능으로 바로 일반화하면 과장입니다.

03 Dev 선정 이유: 에이전트 운영 기능 GA

Claude Platform, 화면 조작·조직 스킬·파일 저장을 한 흐름으로 묶었다

Anthropic은 computer use, Skills API, Files API를 일반 제공으로 전환하고 browser use 도구를 추가했습니다. 에이전트가 화면을 조작하고 조직의 절차를 불러와 문서를 완성하는 전 과정을 플랫폼 기능으로 다루려는 변화입니다.

픽셀과 페이지 구조를 함께 본다

새 browser use는 스크린샷뿐 아니라 페이지 구조를 읽어 좌표가 아닌 특정 필드와 버튼을 겨냥합니다. 웹 자동화의 취약한 클릭 지점을 줄이려는 접근입니다.

한 턴에 여러 동작

업데이트된 computer use는 모델 호출 한 번에 여러 행동을 수행할 수 있습니다. Anthropic은 더 적은 호출과 짧은 완료 시간을 기대합니다.

절차는 버전 있는 스킬로

파일 저장소 1TB

Files API는 조직당 1TB와 기존 대비 5배 높은 요청 한도를 제공합니다. 같은 문서를 매번 다시 보내지 않고 ID로 재사용할 수 있습니다.

Codex CLI 0.149.0, 에이전트를 찾고 열고 메시지 보내는 대시보드를 추가

03 Dev 선정 이유: 대화에서 PR까지의 연결

GitHub Copilot이 Slack에 들어왔다, 대화에서 조사·수정·PR까지

GitHub는 Slack의 @GitHub 멘션으로 Copilot cloud agent 세션을 시작하는 공개 프리뷰를 열었습니다. 팀이 문제를 논의한 문맥에서 바로 조사와 코드 변경을 맡기고, 결과를 PR로 이어갈 수 있습니다.

Slack 대화가 작업 맥락

DM·채널·스레드에서 코드와 GitHub 활동을 묻고, 버그 분류·이슈 생성·수정 작업을 시작할 수 있습니다.

안전한 클라우드 샌드박스에서 검증

Copilot은 실패를 조사하고 코드를 바꾼 뒤 검증해 PR을 엽니다. 작업은 비동기로 이어지고 사용자는 Slack에서 방향을 바꿀 수 있습니다.

팀이 함께 보는 에이전트 세션

전용 코드 채널에서 계획, diff, HTML 같은 결과물을 함께 보고 누구나 추가 맥락을 주거나 세션을 중지할 수 있습니다.

Business·Enterprise 공개 프리뷰

기존 GitHub 권한과 Copilot 예산이 적용되며, 관리자는 에이전트가 만든 PR에 추가 승인을 요구할 수 있습니다.
