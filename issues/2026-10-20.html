01 Icebreaker 선정 이유: AI 답변의 출처 이동

AI 검색이 답만 보여주지 않고, 원문으로 가는 길을 넓힌다

Google은 AI Mode와 AI Overviews의 답변에서 인라인 링크를 더 앞쪽에 배치하고, 공식 사이트와 시의성 있는 기사를 눈에 띄게 보여주는 업데이트를 발표했습니다. AI 요약을 읽는 흐름과 원문을 확인하는 흐름을 더 가깝게 붙이는 변화입니다.

답변 중간에서 바로 원문으로

AI가 생성한 문장 속 핵심 단어나 구절에 연결되는 링크를 더 자주, 더 위쪽에 보여줍니다. 요약을 다 읽은 뒤가 아니라 판단이 필요한 순간 원문을 열기 쉬워집니다.

공식 사이트는 별도 영역으로

정확한 절차나 공식 정보를 찾는 질문에는 관련 공식 페이지를 답변 상단의 전용 영역에 보여주는 표시를 시험합니다. 아직 테스트 단계라 모든 검색에 적용된 기능은 아닙니다.

뉴스 캐러셀은 더 넓은 지역으로

시의성 있는 기사 캐러셀을 더 많은 위치와 언어로 확대하고, 사용자가 고른 Preferred Sources도 함께 강조합니다. 출처 선택권을 AI 요약 안으로 가져오는 흐름입니다.

링크 수보다 도달 가능성

출처 링크가 있다는 사실만으로 검증이 끝나지는 않습니다. 어떤 주장에 어느 원문이 연결되는지, 공식 페이지와 해설 기사가 구분되는지를 함께 봐야 합니다.

02 Main 선정 이유: 기술 문서 검토

Deep Review, 복잡한 문서의 논리와 근거를 다시 읽는다

Google Research는 복잡한 기술 문서의 논리, 수학, 인용 근거를 여러 관점에서 점검하는 Deep Review를 공개했습니다. 초안을 대신 쓰는 AI가 아니라, 사람이 결론을 내리기 전에 반례와 빠진 근거를 찾아주는 검토 에이전트에 가깝습니다.

여러 검토 관점을 병렬로

문서를 논리 구간으로 나눈 뒤 전문 에이전트가 각 구간의 논리, 수학, 근거를 병렬로 검토하고 결과를 합칩니다. 한 번의 요약보다 반박 가능한 지점을 찾는 데 초점을 둡니다.

주 2회 무료 리뷰

전 세계에서 주 2회 무료로 사용할 수 있고, 추가 사용에는 Gemini API 키가 필요합니다. 현재는 PDF와 일반 텍스트를 지원하며 여러 파일을 한 번에 다루는 기능은 추후 예정입니다.

학습엔 미사용, 화면 표시용 1년 보관

업로드 문서는 Google 모델의 학습·미세조정·개선에 쓰이지 않는다고 명시돼 있습니다. 다만 사용자 화면에 보여주기 위해 1년간 저장되므로 민감 문서는 보관 조건을 먼저 확인해야 합니다.

최종 판단은 사람에게 남는다

Deep Review는 공식 학회 심사를 대체하지 않습니다. 중요한 문서에서는 지적된 문제와 놓친 문제를 사람이 다시 확인해야 합니다.

02 Main 선정 이유: 발표자료 공동 작업

ChatGPT Slides, 대화에서 만든 발표자료를 팀이 함께 고친다

OpenAI는 대화, 파일, 개요, 참고 자료를 바탕으로 발표자료를 만들고 같은 공간에서 직접 편집하는 ChatGPT Slides를 출시했습니다. AI가 파일을 건네고 끝나는 대신 사람과 팀이 산출물을 계속 다듬는 작업 흐름을 제품 안에 넣었습니다.

텍스트·도형·차트를 직접 편집

슬라이드의 텍스트, 이미지, 도형, 표와 차트를 사람이 직접 바꾸거나 ChatGPT에 수정을 요청할 수 있습니다. 참고 덱을 공유해 스타일과 레이아웃의 기준으로 삼을 수도 있습니다.

같은 덱에서 실시간 협업

팀원을 초대해 같은 발표자료를 동시에 편집하고 공유 댓글을 남길 수 있습니다. 출시 시점에는 댓글 전용 권한이 제공되지 않는다는 제한이 있습니다.

PPT·PDF·Google Slides로 이동

웹에서는 PowerPoint, PDF, Google Slides로 내보낼 수 있습니다. 데스크톱에서는 설치된 PowerPoint나 Keynote로 열 수 있지만 내보낸 뒤 내용과 레이아웃 검토는 여전히 필요합니다.

Space 접근 요금제부터

웹과 데스크톱의 Space를 쓸 수 있는 적격 Pro·Business·Enterprise 사용자에게 순차 제공됩니다. 계정에 보이지 않으면 아직 롤아웃 대상이 아닐 수 있습니다.

02 Main 선정 이유: 음성 에이전트 설계

목소리의 느낌을 글로 설명해 음성 에이전트에 붙인다

OpenAI는 텍스트로 목소리의 성격을 설명하면 GPT-Live 세션에서 재사용할 수 있는 음성을 만드는 prompt-to-voice를 모든 API 고객에게 공개했습니다. 음성 에이전트의 말투와 인상을 샘플 파일이 아니라 언어로 설계하는 방식입니다.

텍스트 묘사로 맞춤 음성

API나 Voice Playground에서 속도, 온도, 억양 같은 특성을 글로 설명해 음성을 만듭니다. 생성된 음성은 이후 GPT-Live 세션에서 반복해서 사용할 수 있습니다.

한국어 Noeul 포함 9개 음성

독일어, 프랑스어, 힌디어, 일본어와 함께 한국어용 Noeul이 추가됐습니다. 실제 자연스러움과 브랜드 적합성은 언어·문장별로 직접 들어봐야 합니다.

음성 생성은 무료, 발화는 과금

prompt로 음성을 만드는 작업 자체는 무료입니다. 실제 음성을 생성해 대화하는 과정은 일반 GPT-Live 세션 요금이 적용됩니다.

GPT-Live 전용

맞춤 음성은 GPT-Live에서만 사용할 수 있고 기존 TTS나 Chat Completions API에는 적용되지 않습니다. 음성 복제나 실제 인물 사칭 기능으로 소개해서는 안 됩니다.

02 Main 선정 이유: 프런티어 모델 학습 효율

Microsoft의 MAI-Base-2, 모델보다 학습 과정의 설계를 공개했다

Microsoft AI는 2.8조 파라미터 규모의 혼합 전문가 모델 MAI-Base-2의 사전학습을 마쳤다고 밝혔습니다. 이번 발표의 핵심은 출시 모델이 아니라 데이터, 평가, 시스템을 함께 조정해 대규모 학습을 끝까지 안정적으로 운영한 과정입니다.

2.8조 중 800억만 활성화

전체 파라미터는 2.8조지만 한 번의 추론에는 약 800억 파라미터가 활성화되는 MoE 구조입니다. 전체 규모와 실제 계산량을 구분해 봐야 합니다.

GB200 16,000개로 38일

사전학습은 NVIDIA GB200 16,000개를 사용해 38일 동안 진행됐습니다. 대규모 모델 개발이 알고리즘뿐 아니라 클러스터 운영과 장애 복구 문제라는 점을 보여줍니다.

평가가 학습 방향을 바꾼다

Microsoft는 데이터 혼합과 모델 설정을 작은 실험과 보류 평가로 반복 조정했다고 설명합니다. 4.2~12.3배 FLOPs 효율은 자체 평가와 스케일링 추정에 기반한 공급사 수치입니다.

아직 일반 출시가 아니다

현재는 후학습 단계이며 일반 사용 가능한 모델로 공개되지 않았습니다. 신뢰 파트너 대상 가중치 라이선스 방향은 밝혔지만 시점과 조건은 확정되지 않았습니다.

03 Dev 선정 이유: 보안 수정의 검증 루프

Agentic Autofix, 보안 경고를 고치고 다시 검사해 PR로 남긴다

GitHub의 Agentic Autofix가 정식 출시됐습니다. 코드 스캔 경고를 Copilot에 맡기면 관련 파일을 탐색하고 수정한 뒤 CodeQL을 다시 실행하며, 검증된 변경을 검토용 draft PR로 만듭니다.

수정 뒤 CodeQL을 다시 실행

단순 패치 생성에서 끝나지 않고 같은 경고가 해결됐는지 CodeQL로 재검사합니다. 실패하면 수정 과정을 반복해 결과와 검증을 한 흐름으로 묶습니다.

최대 25개 경고를 한 PR로

관련 보안 경고를 최대 25개까지 묶어 하나의 draft PR로 만들 수 있습니다. 변경 범위가 커질수록 사람이 영향과 회귀를 더 꼼꼼히 검토해야 합니다.

기본 브랜치 경고만 대상

GitHub Enterprise Cloud의 Code Security 또는 Advanced Security 고객이 기본 브랜치 경고에 사용할 수 있습니다. 조직·저장소 설정과 Copilot 결제 설정이 필요하고 AI Credits와 Actions 시간이 사용됩니다.

자동 수정 뒤에도 사람 승인

결과는 바로 병합되는 코드가 아니라 검토용 PR입니다. 에이전트가 만든 수정의 정확성, 테스트 통과, 다른 취약점 발생 여부는 사람이 확인해야 합니다.

03 Dev 선정 이유: 자동화 공급망 고정

GitHub Actions도 패키지처럼 실행 버전을 잠근다

GitHub Actions workflow lockfiles가 공개 프리뷰로 나왔습니다. 워크플로에서는 읽기 쉬운 태그나 브랜치 이름을 유지하면서 실제 실행은 검토한 커밋에 고정해, 자동화 의존성이 예고 없이 바뀌는 위험을 줄입니다.

태그는 남기고 커밋은 고정

워크플로 파일에는 v4 같은 표기를 유지하고 lockfile에는 실제 커밋 SHA를 기록합니다. 사람이 읽기 쉬운 설정과 재현 가능한 실행을 함께 가져갑니다.

전이 의존성까지 기록

gh actions-lock은 직접 호출한 Action뿐 아니라 내부에서 이어지는 의존성과 재사용 워크플로도 잠급니다. 실제 실행 경로를 더 넓게 고정합니다.

Dependabot으로 갱신

새 버전이 나오면 Dependabot이 업데이트 PR을 만들고 lockfile 변경을 함께 제안할 수 있습니다. 업데이트 내용을 검토한 뒤 반영하는 흐름을 유지합니다.

고정은 안전성 판정이 아니다

lockfile은 실행 대상이 바뀌지 않게 할 뿐, 그 커밋이 안전하다는 사실을 보장하지 않습니다. 공개 프리뷰 단계이므로 조직 정책 적용 전 동작 범위도 확인해야 합니다.

03 Dev 선정 이유: 사람·에이전트 공유 화면

VS Code Canvas, 에이전트가 만든 결과를 화면에서 함께 다룬다

VS Code 1.142는 에이전트와 사람이 같은 산출물을 보고 고치는 인터랙티브 Canvas를 preview로 추가했습니다. Canvas extension이 제공하는 화면을 채팅 옆에 열어, 프롬프트만 주고받지 않고 작업 상태를 함께 조작하는 방식입니다.

채팅 옆의 공유 작업면

Canvas는 채팅 옆에 열리고 사람과 에이전트가 같은 산출물을 살펴보고 갱신합니다. 화면의 종류와 동작은 설치하거나 직접 만든 canvas extension이 정합니다.

칸반 카드도 함께 움직인다

칸반 캔버스에서는 사람이 카드를 옮기고, 에이전트가 기능을 작업으로 쪼개거나 상태와 새로 발견한 할 일을 갱신할 수 있습니다. 계획과 실행 상황을 같은 화면에서 공유합니다.

필요한 화면을 직접 만든다

채팅에서 /create-canvas와 원하는 인터페이스를 설명하면 작업공간에 canvas extension을 만들 수 있습니다. 커뮤니티의 샘플 확장을 설치하는 경로도 제공됩니다.

데스크톱 로컬 세션의 Preview

Canvas는 VS Code 데스크톱에서 Copilot harness를 쓰는 로컬 세션에 한해 제공됩니다. chat.canvases.enabled 설정을 켜고 새 세션을 시작해야 합니다.
