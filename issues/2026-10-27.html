여성 조각가 18명의 기록

02 Main 선정 이유: 화면 조작 비용 절감

GPT-6.1 Terra, 화면을 보고 움직이는 AI의 비용 문턱을 낮춘다

OpenAI는 시각 이해와 컴퓨터 사용에 초점을 둔 GPT-6.1 Terra를 출시했습니다. 서류 입력, 기술 도면 해석, 영상 편집처럼 화면을 읽고 직접 조작하는 고빈도 업무를 더 빠르고 저렴하게 처리하려는 모델입니다.

기존 Terra보다 API 가격 50% 낮게

표준 API 가격은 입력 100만 토큰당 1달러, 캐시 입력 0.05달러, 출력 5달러입니다. GPT-5.6 Terra와 GPT-6.1 Sol의 표준 가격보다 50% 낮다고 OpenAI는 설명합니다.

화면 작업 성적은 높고 비용은 낮게

OpenAI 자체 Agents' Last Exam에서 중간 추론 기준 GPT-5.6 Terra보다 15%포인트 높고 비용은 약 3분의 1이었다고 발표했습니다. 공급사 벤치마크이므로 실제 업무에서는 별도 평가가 필요합니다.

코딩도 개선, 최고 난도는 Sol·Astra

Terminal-Bench 4.0 최대 추론에서 50.3%를 기록해 GPT-5.6 Terra의 공개 점수 21.5%를 넘었습니다. 다만 복잡한 코딩은 Sol과 Astra가 더 적합하다고 명시했습니다.

Work·Codex·API에 같은 날

Plus, Pro, Enterprise, Edu 사용자는 ChatGPT Work와 Codex에서 쓸 수 있고 API 모델명은 gpt-6.1-terra입니다. 사이버 보안 능력은 Preparedness Framework의 Critical 기준에 해당합니다.

02 Main 선정 이유: 클라우드 모델 선택권

OpenAI 모델과 Codex, Google Cloud의 모델 정원에 제공될 예정이다

OpenAI와 Google Cloud는 OpenAI의 프런티어 모델과 Codex 에이전트 흐름을 Google Cloud Model Garden에 제공하기로 했습니다. 기업은 기존 Google Cloud의 접근 제어와 청구 체계 안에서 OpenAI 모델을 평가하고 도입할 수 있게 됩니다.

Model Garden에서 네이티브 접근

일반 제공 뒤에는 Google Cloud 고객이 익숙한 클라우드 환경에서 OpenAI 모델과 Codex를 선택해 에이전트 흐름을 만들 수 있게 됩니다. 별도 실험 계정과 운영 환경 사이의 이동을 줄이는 변화입니다.

GCP 약정 금액으로 구매

Google Cloud Marketplace를 통해 구매하고 기존 GCP 사용 약정을 소진하는 데 활용할 수 있습니다. 계약·가격·지역별 조건은 실제 제공 시점에 다시 확인해야 합니다.

Antigravity와 Gemini Agent에도 예정

OpenAI 모델은 Google Antigravity와 Gemini Agent에도 들어갈 예정입니다. 한 에이전트 제품 안에서 과제에 따라 모델을 고르는 방향을 보여줍니다.

02 Main 선정 이유: 접속 경로별 안전 기준

같은 OpenAI 모델을 어디서 써도, 안전정책은 함께 따라간다

OpenAI는 자사 서비스, 파트너 호스팅, 리셀러 등 서로 다른 경로에서 모델을 제공하더라도 같은 수준의 보호조치를 적용하겠다고 밝혔습니다. 모델 유통 경로가 넓어지는 만큼 우회 접속과 책임 공백을 줄이려는 정책 변화입니다.

파트너도 같은 보호조치

OpenAI 모델을 직접 제공하는 파트너는 자체 서비스에서도 OpenAI와 일치하는 보호조치를 유지하고, 위반을 조사하며, 필요한 집행을 조율해야 합니다.

라우터·게이트웨이는 사전 검토

모델 라우터나 AI 게이트웨이처럼 사용자에게 직접 접속을 제공하는 서비스는 OpenAI의 검토와 승인을 받아야 한다는 요구가 새 이용정책에 포함됩니다.

새 정책은 11월 20일 발효

업데이트된 Usage Policies는 2026년 11월 20일부터 적용됩니다. 파트너와 개발자는 제공 경로와 민감한 사용 사례가 새 조건에 맞는지 확인해야 합니다.

SafetyID로 개인 식별은 줄이기

고객이 익명화된 SafetyID를 제공하면 OpenAI가 실제 신원을 알지 않고도 개별 최종 사용자를 구분해 오남용을 조사할 수 있도록 준비하고 있습니다.

02 Main 선정 이유: 공개 음성 모델 선택지

Granite Speech 5.0, 받아쓰기·번역·화자 구분을 열린 모델로 나눈다

IBM은 정확도 중심 2B 모델, 속도 중심 470M 모델, 회의·통화용 화자 구분 모델로 Granite Speech 제품군을 업데이트했습니다. 한 모델로 모든 음성 작업을 해결하기보다 정확도, 속도, 발화자 추적에 맞춰 공개 가중치 모델을 고르는 구성입니다.

2B 모델은 6개 언어 받아쓰기

영어, 프랑스어, 독일어, 스페인어, 포르투갈어, 일본어를 받아쓰고 영어와 상호 번역합니다. 최대 2,000개 전문 용어를 우선 인식하도록 지정할 수 있습니다.

470M 모델은 다국어·엣지용

Turbo CTC는 7개 언어 받아쓰기와 구두점·대문자 출력을 지원합니다. IBM 측 공개 평가에서는 초기 버전보다 약 1.6배 빠른 처리량을 기록했습니다.

회의에서는 누가 말했는지까지

업데이트된 4.1 2B Plus는 화자 구분 오류와 타임스탬프 오차를 줄이고 긴 녹음의 WER를 24% 낮췄다고 발표했습니다. 수치는 IBM의 공개 테스트 기준입니다.

Apache 2.0, 한국어는 미지원

세 모델 모두 Apache 2.0으로 공개되고 Transformers를 지원합니다. 발표된 지원 언어에 한국어는 없으며 실제 소음 환경과 도메인 용어 정확도는 별도 검증이 필요합니다.

03 Dev 선정 이유: 에이전트 구조 단순화

서브에이전트를 늘리기 전에, 하나의 루프로 합쳐 성능을 비교한다

Anthropic은 여러 라우터·플래너·도메인 에이전트를 하나의 메인 루프와 필요할 때만 읽는 Skills·도구로 합치는 설계 가이드를 공개했습니다. 핵심은 멀티에이전트를 금지하는 것이 아니라 대표 과제에서 품질·비용·지연을 비교해 필요한 분리만 남기는 것입니다.

한 컨텍스트에서 계획과 실행

계획을 만든 모델이 같은 컨텍스트에서 도구 결과를 보고 다음 단계를 바꿉니다. 서브에이전트 사이의 요약 전달에서 세부 정보가 사라지는 문제를 줄이려는 구조입니다.

Skills와 도구는 필요할 때만

짧은 설명만 먼저 보여주고 필요한 지침과 도구 정의를 그때 불러오는 progressive disclosure를 권합니다. 긴 시스템 프롬프트를 모두 넣는 방식과 구분됩니다.

골든 예시 10개부터 비교

작은 종단 간 평가 세트를 만든 뒤 서브에이전트를 하나씩 합치고 성공률·지연·비용을 여러 번 비교하라고 안내합니다. 구조가 단순하다는 이유만으로 개선을 단정하지 않습니다.

검증·병렬 작업은 계속 분리

독립 검증, 서로 겹치지 않는 병렬 작업, 권한 분리가 필요하면 서브에이전트가 여전히 유효합니다. 조직도를 그대로 에이전트 구조로 복제하는 관행을 경계합니다.

03 Dev 선정 이유: 에이전트 설치 안전장치

GitHub package firewall, 에이전트가 설치하기 전에 패키지를 검사한다

GitHub는 10월 20일 package firewall을 공개하고 21일 설명을 보완했습니다. 코딩 에이전트와 CI가 사람 확인 없이 의존성을 설치할 때, 패키지 저장소 앞에서 메타데이터와 실제 다운로드를 정책에 따라 검사하는 공개 프리뷰입니다.

설치 요청과 파일을 모두 검사

패키지 목록을 묻는 메타데이터 요청과 실제 다운로드가 방화벽을 통과합니다. 관리자가 정한 정책에 맞지 않으면 설치를 막고 예외 요청 흐름을 제공합니다.

새 패키지는 냉각 기간

등록 직후 패키지를 일정 시간 막는 cooldown, GitHub Advisory Database의 악성코드·취약점 확인, attestation 약화 같은 공급망 정책을 설정할 수 있습니다.

Enterprise Cloud 공개 프리뷰

GitHub Enterprise Cloud와 데이터 레지던시 고객에게 제공되며 프리뷰 기간에는 무료입니다. 정식 출시 뒤에는 Actions처럼 사용량 과금이 예정돼 있습니다.

현재는 npm만 지원

개발 환경과 CI의 패키지 요청을 방화벽으로 보내도록 별도 구성해야 하며 지금은 npm 패키지만 지원합니다. 모든 언어의 공급망 보호 기능으로 소개하면 안 됩니다.

03 Dev 선정 이유: 알림에서 수정 PR까지

Teams에 온 버그 알림이 Copilot의 수정 PR로 이어진다

GitHub는 Microsoft Teams용 통합 앱에 Copilot 작업 흐름을 붙였습니다. 채널이나 개인 대화에 버그 알림이 오면 @GitHub를 불러 이슈를 조사하고 코드를 수정해 PR을 만들도록 맡길 수 있습니다.

대화창에서 바로 조사 요청

채널, 그룹 채팅, 개인 채팅에서 GitHub 알림을 받고 같은 자리에서 에이전트 작업을 시작합니다. 알림 확인과 저장소 이동 사이의 단계를 줄입니다.

이슈에서 수정 PR까지

Copilot이 버그 이슈를 조사하고 수정안을 만들어 PR로 남깁니다. 최종 흐름은 팀이 변경 내용을 검토하고 테스트한 뒤 병합하는 단계로 끝납니다.

통합 GitHub 앱으로 업데이트

기존 GitHub notifications 앱 사용자는 최신 버전으로 업데이트하면 됩니다. GitHub 계정을 연결하고 작업할 저장소를 선택해야 합니다.

구형 앱은 11월 16일 종료

GitHub (deprecated)로 이름이 바뀌는 구형 앱은 11월 16일 종료될 예정입니다. 발표문에는 Copilot 플랜별 이용 조건이 구체적으로 적혀 있지 않습니다.

04 Research 선정 이유: 실행 전 검증·장애·기억 연구 5선

이번 주 연구 노트: 에이전트는 실행 전 상태와 실패 뒤 복구까지 평가해야 한다

StateMirror: 실행 전에 틀린 전제를 잡는다
