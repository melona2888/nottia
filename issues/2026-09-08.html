Nottia Weekly Newsletter / 15호 2026.09.02 - 2026.09.08

AI가 더 강해지고, 일마다 다른 모델과 실행 방식을 고른 주

GPT-6 Astra와 Gemini 3.8은 장기 작업과 사이버 방어를 전면에 세웠고, 날씨·음성·음악 모델은 전문 업무로 더 깊이 들어갔습니다. 개발도구 쪽에서는 한 모델을 고르는 대신 여러 모델과 검증 단계를 조합하는 방식이 제품이 되기 시작했습니다.

This Week in 4 Lines

  1. GPT-6 Astra는 컴퓨터 사용과 장기 코딩을 강화했지만, 사이버 역량이 높아지며 더 강한 감시와 승인 절차도 함께 붙었습니다.
  2. Gemini 3.8은 빠른 범용 모델과 제한 접근 사이버 모델을 같은 기반에서 나눠, 능력보다 배포 경계가 중요해졌음을 보여줬습니다.
  3. WeatherNext 3와 MAI-Transcribe-2는 실시간 위성·다국어 음성을 제품과 API에 바로 연결해 전문 모델의 실사용 면적을 넓혔습니다.
  4. HydraFusion, 콘텐츠 제외, Agent Merge는 코딩 에이전트의 경쟁축을 단일 모델 점수에서 라우팅·보호·검증을 포함한 실행 시스템으로 옮겼습니다.

Editorial Note

이번 주에는 가장 강한 모델 하나를 모든 일에 쓰는 그림이 빠르게 낡았습니다. 같은 기반 모델도 일반 작업과 고위험 보안 작업의 접근을 나누고, 개발도구는 초안·비평·승격을 다른 모델에 맡깁니다. 앞으로의 차이는 모델 이름보다 어떤 일을 누구에게 맡기고 어디서 멈추게 하는지에서 더 크게 벌어질 가능성이 높습니다.

01 Icebreaker 선정 이유: 누구나 만나는 생성 음악

Gemini가 장르와 길이를 고르면 노래 한 곡을 만드는 도구가 됐다

Google은 9월 4일 음악 생성 모델 Lyria 3.5를 Gemini 앱과 API에 공개했습니다. 짧은 효과음보다 완성된 트랙 제작에 초점을 맞추며, 일반 사용자와 창작자·개발자가 같은 모델을 서로 다른 화면에서 쓸 수 있게 했습니다.

보컬 표현과 편곡을 함께 개선

Google은 이전보다 표현력 있는 보컬과 풍부한 편곡, 높은 음질을 주요 변화로 제시했습니다.

장르·보컬·길이를 직접 선택

Gemini 앱에서 장르를 설명하거나 고르고, 보컬·연주곡과 짧은 곡·긴 곡을 선택할 수 있습니다.

앱과 API를 동시에 열었다

웹·모바일 Gemini 전 세계 사용자와 AI Studio, Gemini API, Google Vids 이용자가 각자 작업 흐름에 붙일 수 있습니다.

음질 평가는 아직 제조사 설명

공식 발표는 기능과 가용성을 설명하지만 독립 청취 평가나 모든 사용 시나리오의 권리 조건까지 검증한 자료는 아닙니다.

02 Main 선정 이유: 장기 에이전트의 기준점

GPT-6 Astra는 ‘답을 내는 모델’보다 오래 일하고 스스로 검증하는 에이전트에 맞춰졌다

OpenAI는 9월 3일 GPT-6 Astra를 공개했습니다. 컴퓨터 사용, 소프트웨어 엔지니어링, 과학·전문 업무를 한 모델에 묶었고, Codex에서는 긴 작업 중 쌓인 메모와 과거 문맥을 다시 찾는 실험 기능도 소개했습니다.

긴 세션의 실패 이유를 다시 찾는다

Codex의 실험 기능은 문맥이 가득 찬 뒤에도 메모를 보존하고 이전 대화·도구 출력에서 요구사항과 테스트 결과를 검색합니다.

컴퓨터 작업 점수가 72.6%

OpenAI 평가에서 OSWorld 2.0은 72.6%로 GPT-5.6 Sol의 65.7%보다 높았습니다. 생산 환경의 도구·설정에 따라 결과는 달라질 수 있습니다.

사이버 역량이 ‘Critical’ 단계

OpenAI는 Astra를 Preparedness Framework상 Critical cyber capability에 도달한 첫 광범위 배포 모델로 분류하고 감시·격리·승인 장치를 강화했습니다.

순차 출시, 입력 100만 토큰당 10달러

Plus·Pro·Business·Enterprise와 API, Azure, Bedrock에 순차 제공됩니다. API 표준가는 입력 10달러, 출력 50달러이며 기업은 기본 비활성입니다.

OpenAI · GPT-6 Astra
02 Main 선정 이유: 같은 지능, 다른 접근 경계

Gemini 3.8은 범용 Flash와 신뢰된 방어자용 Cyber로 배포 경계를 나눴다

Google은 9월 2일 Gemini 3.8 Flash와 3.8 Flash Cyber를 함께 발표했습니다. 공통 기반 지능을 쓰지만, 일반 코딩·추론 모델은 넓게 공개하고 더 완화된 사이버 보호장치가 필요한 모델은 제한 프로그램에만 제공했습니다.

3.7과 같은 속도·한시 가격

3.8 Flash는 입력 100만 토큰당 0.75달러, 출력 3.75달러의 도입가를 유지합니다. 이 가격은 2026년 말까지만 적용됩니다.

더 오래 생각하면 토큰도 늘어난다

복잡한 작업에서 추가 추론과 도구 호출을 수행해 성능을 높이지만, Google도 높은 effort에서는 토큰 사용량이 늘 수 있다고 명시했습니다.

Cyber는 패치에 초점을 맞췄다

내부 20개 언어 취약점 평가 성공률은 70%를 넘었고, 외부 CWE-Bench 패치 평가 pass@1은 47.2%였습니다.

일반 사용과 보안 접근을 분리

Flash는 AI Studio·Gemini 앱·Search 등에서 제공되지만 Cyber는 정부·핵심 인프라·소프트웨어 유지관리자 등 승인된 방어자 대상입니다.

Google · Gemini 3.8 Flash and Cyber
02 Main 선정 이유: 실시간 데이터의 제품화

WeatherNext 3는 여섯 시간 늦은 시뮬레이션 대신 실시간 위성으로 매시간 예보한다

Google DeepMind와 Google Research는 9월 3일 WeatherNext 3를 공개했습니다. 원시 위성 관측을 직접 받아 예보를 갱신하고, 연구 모델에 머물지 않고 Search·Gemini·Maps와 Cloud 데이터 제품에 즉시 연결했습니다.

6시간 지연을 실시간 위성으로 교체

이전 AI 날씨 모델이 주로 수치예보 시뮬레이션을 학습한 것과 달리, 최신 정지궤도 위성 관측을 직접 반영합니다.

25km에서 최대 5km 해상도

WeatherNext 2의 25km 격자보다 최대 다섯 배 촘촘한 5km 해상도로 지역 지형과 빠른 강수 변화를 더 세밀하게 표현합니다.

장기 강수 정확도 최대 50% 향상

Google은 하루 이상 앞선 강수 예보가 최대 50% 더 정확해졌다고 밝혔으며, 기존 예보가 약한 지역에서 개선 폭이 컸다고 설명했습니다.

검색·지도·클라우드에 같은 예보

Search, Gemini, Maps, Maps Platform API, Earth Engine에서 제공됩니다. 재난 경보는 지역 기상청의 공식 정보를 우선해야 합니다.

02 Main 선정 이유: 음성을 구조화된 기록으로

MAI-Transcribe-2는 화자·단어 시간·전문용어까지 한 번에 기록한다

Microsoft AI는 9월 3일 다국어 음성인식 모델 MAI-Transcribe-2를 공개했습니다. 단순 받아쓰기보다 회의·의료·법률 기록처럼 누가 언제 무엇을 말했는지와 전문용어를 함께 보존하는 작업에 초점을 맞췄습니다.

60개 언어 평균 오류율 5.2%

Microsoft가 공개 벤치마크 FLEURS에서 측정한 평균 단어 오류율입니다. 실제 잡음·도메인·언어 조합에서는 별도 검증이 필요합니다.

화자와 단어 시간을 함께 표시

화자 분리와 단어 단위 타임스탬프를 지원해 회의 검색, 자막 편집, 발언별 기록을 만들기 쉬워졌습니다.

전문용어와 혼합 언어를 보정

키워드 편향으로 이름·약어를 우선 인식하고, 대화 중 언어가 바뀌는 코드 스위칭도 처리합니다.

시간당 0.10달러는 한시 가격

연말까지 한시적으로 적용되며 Foundry, MAI Playground, OpenRouter에서 데모할 수 있습니다. 최대 10배 속도 주장은 발표사와 인용 평가 기준입니다.

03 Dev 선정 이유: 모델 선택을 실행 흐름으로

HydraFusion은 한 모델을 고르는 대신 초안·비평·승격 경로를 자동으로 고른다

GitHub은 9월 4일 Copilot CLI 연구 프리뷰인 Project HydraFusion을 공개했습니다. 사용자는 하나의 모델처럼 선택하지만, 내부에서는 작업 난이도에 따라 여러 공급자의 모델과 검증 단계를 조합합니다.

Single·Cascade·Critique 세 갈래

한 모델이 바로 풀거나, 저비용 초안을 품질 게이트 뒤 상위 모델로 넘기거나, 다른 계열 모델이 읽기 전용 비평을 맡습니다.

필요할 때만 비싼 추론을 호출

모든 작업을 최고가 모델에 보내지 않고 품질·비용·지연 조건을 함께 보고 가장 단순한 실행 경로를 고릅니다.

오프라인 평가 비용 67% 절감

TerminalBench 2.1에서 Opus 5 대비 검증 품질은 4.9%p 높고 추정 비용은 67% 낮았습니다. 고정 벤치마크·정책 조건의 결과입니다.

모든 Copilot 플랜의 실험 기능

Copilot CLI의 /experimental에서 사용할 수 있습니다. 현재는 잘 정의된 단일 프롬프트 작업에 맞고 장기 다중 턴은 개선 중입니다.

GitHub · Project HydraFusion
03 Dev 선정 이유: 에이전트 문맥의 최소 권한

Copilot 앱과 CLI가 관리자가 제외한 파일을 에이전트 문맥에서 빼기 시작했다

GitHub Copilot의 콘텐츠 제외 정책이 9월 2일 앱과 CLI까지 일반 제공됐습니다. 저장소 안의 모든 파일을 에이전트가 읽는 전제를 버리고, 민감 코드와 설정을 조직 정책으로 문맥에서 분리할 수 있게 됐습니다.

제외 파일은 프롬프트 문맥 밖으로

관리자가 지정한 파일은 Copilot 앱과 CLI의 에이전트 작업에서 컨텍스트로 사용되지 않습니다.

기업·조직·저장소 정책을 상속

개별 사용자의 주의에만 맡기지 않고 세 수준의 관리 정책을 같은 에이전트 흐름에 적용합니다.

Business와 Enterprise 대상

현재 일반 제공 범위는 Copilot Business와 Enterprise입니다. 개인 플랜 전체에 적용되는 기능은 아닙니다.

비밀 관리 자체를 대신하진 않는다

문맥 제외는 노출 면을 줄이는 장치입니다. 저장소 비밀 스캔, 접근권한, 키 회전 같은 기본 통제를 대체하지 않습니다.

03 Dev 선정 이유: PR 마무리 자동화

VS Code의 Agent Merge가 리뷰 지적·실패한 검사·충돌을 한 흐름에서 정리한다

GitHub의 9월 4일 주간 릴리스는 VS Code 1.136의 Agent Merge와 다중 루트 에이전트 세션을 묶어 소개했습니다. 코드를 만드는 단계보다 PR을 합칠 수 있는 상태로 정리하는 후반 작업까지 에이전트 범위가 넓어졌습니다.

리뷰·검사·충돌을 한 번에 추적

Agent Merge는 리뷰 피드백, 실패한 검사, 병합 충돌을 해결해 PR을 merge-ready 상태로 만드는 공개 프리뷰입니다.

여러 폴더에 에이전트 세션 연결

실험적 multi-root workspace는 한 작업공간의 각 폴더에서 Copilot과 Claude 에이전트 세션을 사용할 수 있게 합니다.

세션을 계층으로 묶고 주의 신호 표시

관련 채팅을 계층 구조로 정리하고 사용자의 확인이 필요한 세션을 구분해, 병렬 작업의 상태를 보기 쉽게 했습니다.

GA와 Preview와 Experimental이 섞였다

같은 릴리스 묶음 안에서도 성숙도가 다릅니다. 실제 프로젝트 적용 전 기능별 상태와 되돌리기 경로를 따로 확인해야 합니다.

04 Research 선정 이유: 에이전트 시스템의 다음 병목

이번 주 연구 5선: 모델보다 스킬·하니스·평가 환경을 다시 설계한다

이번 주 논문들은 더 큰 기반 모델 하나보다, 운영 지식을 압축하고 안전 정책을 실행계와 함께 학습하며 실제 고객 조건에 가까운 환경에서 에이전트를 평가하는 방향을 보여줍니다.

Repo-To-Skill: 저장소 노하우를 재사용 스킬로

1,000개 ML 저장소에서 5,000개가 넘는 검증 스킬을 추출해 에이전트의 시행착오를 줄입니다. 성능 향상은 GPT-5.5 기반 특정 연구 하니스 조건입니다. arXiv

SafeEvolve: 하니스와 정책을 함께 진화

위험한 실행 궤적을 근거로 안전 프롬프트·스킬과 모델 정책을 함께 갱신합니다. AgentDojo 중심 결과가 실제 서비스의 모든 권한 위험을 보장하진 않습니다. arXiv

SolarWM: 5초 학습에서 긴 세계 시뮬레이션으로

서로 다른 영상 데이터와 5B~33B 모델을 공통 계약으로 묶어 분·시간 단위 상호작용을 목표로 합니다. 긴 생성의 물리 일관성은 추가 검증이 필요합니다. arXiv

Iris: 검색보다 문맥 관리가 성능을 가른다

검색할 것과 멈출 시점을 SFT·실시간 검색 RL로 학습한 오픈 에이전트입니다. 논문도 추론 중 문맥 관리가 모델 간 차이보다 클 수 있다고 지적합니다. arXiv

τ^τ-Bench: 고객 조건에서 에이전트를 직접 구축

업무 기록·API·비용 제한을 받아 고객지원 에이전트를 만드는 평가입니다. 최고 설정도 시뮬레이션 통과율 23.9%로 완성형과의 거리를 드러냈습니다. arXiv
