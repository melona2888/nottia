Figma의 Chrome 확장 프로그램은 웹 페이지 전체나 특정 요소를 캡처해 단순 스크린샷이 아닌 구조화된 디자인 레이어로 옮깁니다. 운영 중인 화면을 다시 만들지 않고 곧바로 개선안과 프로토타입의 출발점으로 삼을 수 있습니다.

스크린샷 대신 구조화 레이어

페이지 전체 또는 특정 요소를 캡처해 Figma 캔버스의 디자인 레이어로 가져옵니다. 텍스트와 요소를 분리해 다시 만질 수 있다는 점이 핵심입니다.

현재 제품에서 바로 리디자인

운영 화면을 기준으로 색, 배치, 문구를 바꾸며 개선안을 만들 수 있습니다. 오래된 디자인 파일을 찾는 시간도 줄어듭니다.

Figma Make로 바로 연결

캡처한 디자인을 Figma Make에 보내 작동하는 프로토타입의 출발점으로 쓸 수 있습니다. 캡처→편집→동작 확인이 한 흐름이 됩니다.

복제보다 출처와 권한 확인

02 Main 선정 이유: 팀 협업 변화

Claude Code Artifacts, 작업 과정을 ‘같은 링크’로 공유한다

Claude Code는 조사와 구현 진행 상황을 PR 워크스루, 시스템 설명, 대시보드, 릴리스 체크리스트 같은 인터랙티브 웹 페이지로 발행할 수 있게 됐습니다. 에이전트가 다시 발행하면 같은 URL의 내용이 갱신됩니다.

세션 맥락이 바로 설명 페이지로

코드베이스, 연결된 도구, 대화 맥락을 묶어 별도 대시보드 인프라 없이 작업 설명 페이지를 만듭니다.

URL은 유지, 버전은 쌓임

업데이트를 발행할 때 열린 페이지가 같은 주소에서 새로고침되고 버전 이력이 남습니다. 진행 보고와 최종 산출물이 분리되지 않습니다.

리뷰 가능한 에이전트 작업

에러 타임라인, 의심 커밋, 테스트 결과처럼 작업 중 근거를 시각적으로 보여줄 수 있어 결과만 던지는 에이전트보다 검토가 쉬워집니다.

공개 링크는 아님

02 Main 선정 이유: 일상 자동화

ChatGPT Scheduled Tasks, 알림을 넘어 ‘변화가 있을 때만 보고’한다

ChatGPT 예약 작업은 사이드바의 전용 Scheduled 페이지, 시간대 범위 예약, 웹과 연결 앱을 확인하는 모니터링 작업을 추가했습니다. OpenAI는 Pulse의 선제적 업데이트 역할도 이 기능으로 옮깁니다.

예약 작업 전용 관리 화면

활성 작업, 다음 실행 시각을 한곳에서 보고 일시정지·재개·수정·삭제할 수 있습니다. 채팅 속에 흩어진 예약을 찾는 문제가 줄어듭니다.

웹·연결 앱 변화 감시

모니터링 작업은 웹과 연결 앱을 확인하고 보고할 변화가 있을 때만 알립니다. 매일 같은 내용의 알림보다 조건형 자동화에 가깝습니다.

정확한 시각 또는 넓은 시간대

특정 시각뿐 아니라 아침·오후·저녁 같은 범위로도 예약할 수 있습니다. 일정 자동화의 표현이 조금 더 자연스러워졌습니다.

시간당 1회가 상한

Plus·Pro·Business·Enterprise에 순차 배포되며 활성 작업 한도는 플랜마다 다릅니다. 작업은 시간당 1회를 넘겨 실행할 수 없습니다.

02 Main 선정 이유: AI 코딩 시장 재편

SpaceX, Cursor를 품는다—모델 다음 전장은 개발자 유통망

SpaceX는 Cursor를 만드는 Anysphere와 600억 달러 규모의 확정적 합병계약을 체결했습니다. 거래가 끝나면 Anysphere는 SpaceX의 완전 자회사가 됩니다. 컴퓨트 인프라와 모델을 가진 회사가 개발자가 매일 쓰는 코딩 인터페이스까지 직접 확보하려는 움직임입니다.

아직 합병 완료는 아님

6월 16일 계약을 체결했고 규제 승인 등 종결 조건이 남아 있습니다. SpaceX는 2026년 3분기 거래 완료를 예상합니다.

600억 달러 전액 주식 거래

SpaceX의 자회사 X67이 Anysphere에 합병되고 Anysphere가 존속하는 구조입니다. Cursor 주식은 600억 달러의 평가가치를 기준으로 SpaceX Class A 주식으로 전환됩니다.

Cursor와 Grok Build에 공동 모델

SpaceX는 SpaceXAI와 Cursor가 최근 몇 달간 공동으로 모델을 훈련했으며 이를 Cursor와 Grok Build에 곧 공개할 예정이라고 밝혔습니다. 인수의 첫 제품 효과가 어디서 나타날지 보여주는 대목입니다.

독립성과 데이터 경계가 관건

Cursor가 여러 모델을 선택하는 현재 전략을 얼마나 유지할지, 기업 코드와 사용 데이터가 어떤 경계에서 처리될지는 아직 구체적으로 발표되지 않았습니다. 사용자 데이터가 곧바로 모델 학습에 쓰인다고 단정해서는 안 됩니다.

03 Dev 선정 이유: 노코드형 스킬 제작

Codex Record & Replay, 화면으로 한 번 보여주면 스킬 초안을 만든다

말로 길게 설명하기 어려운 반복 작업을 직접 시연하면 Codex가 필요한 입력, 실행 단계, 검증 방법을 담은 재사용 스킬을 작성합니다. 비용 처리, 이슈 생성, 영상 게시, 정기 보고서 다운로드 같은 작업이 대표 예시입니다.

설명보다 시연

사용자가 Mac에서 작업을 수행하는 동안 필요한 동작과 창 내용을 관찰합니다. 숨은 클릭 순서와 개인 선호를 프롬프트보다 쉽게 전달할 수 있습니다.

녹화 후 SKILL 초안

녹화를 멈추면 Codex가 트리거, 입력, 단계, 검증 기준을 정리합니다. 사용자는 초안을 검토하고 예외와 명명 규칙을 보완할 수 있습니다.

Computer Use로 재실행

새 스레드에서 생성된 스킬을 부르면 Computer Use, 브라우저 동작, 설치된 플러그인을 조합해 같은 흐름을 반복합니다.

민감정보는 녹화하지 않기

현재 macOS와 Computer Use가 필요하며 EU·영국·스위스는 초기 제공에서 제외됩니다. 녹화에는 비밀키나 민감 데이터를 넣지 않는 것이 원칙입니다.

03 Dev 선정 이유: 개발 문서 UX

OpenAI 개발 문서, 검색창 옆에 Docs Agent를 세웠다

OpenAI Developers 사이트에는 문서 전체를 대상으로 질문하는 Docs Agent가 들어왔습니다. 새 API보다 작아 보이는 변화지만, 복잡해진 제품군에서 사용자가 문서 구조를 먼저 배우지 않아도 목적에서 관련 페이지로 이동하게 만드는 인터페이스입니다.

키워드보다 목적을 질문

정확한 API 이름을 모르더라도 하려는 일을 설명하며 출발할 수 있습니다. 문서 검색이 메뉴 탐색에서 대화형 안내로 바뀝니다.

답보다 원문 위치가 중요

개발 문서 에이전트의 가치는 요약 자체보다 관련 공식 가이드와 참조 위치로 빠르게 연결하는 데 있습니다.

문서가 제품 인터페이스가 됨

API, Codex, Apps SDK처럼 갈라진 제품군을 한 질문면으로 묶습니다. 앞으로 개발자 포털도 정적 목차보다 에이전트형 진입점이 중요해질 수 있습니다.

최종 확인은 문서 본문

에이전트 답변은 길잡이입니다. 버전, 지역, 가격, 제한처럼 배포에 영향을 주는 내용은 연결된 공식 문서에서 다시 확인해야 합니다.

03 Dev 선정 이유: 추가 주간 신호

GitHub Copilot 코드 리뷰, 이제 루트 AGENTS.md를 읽는다

Copilot 코드 리뷰가 저장소 루트의 AGENTS.md를 자동으로 읽고 팀의 관례와 기대를 리뷰 피드백에 반영합니다. 에이전트 지침 파일이 코딩 단계뿐 아니라 리뷰 단계의 공통 계약으로 확장되는 변화입니다.

리뷰 기준을 저장소에 둠

리뷰어마다 반복해서 설명하던 규칙을 루트 AGENTS.md에 남길 수 있습니다. Copilot은 관련 지침을 읽고 피드백 생성에 사용합니다.

기존 파일도 자동 반영

이미 AGENTS.md를 쓰는 저장소는 별도 연결 작업 없이 코드 리뷰 맥락으로 활용됩니다. 기능은 일반 제공 상태입니다.

규칙의 품질이 리뷰 품질

모호하거나 오래된 지침도 그대로 영향을 줄 수 있습니다. 팀 규칙을 테스트 가능하고 충돌 없이 유지하는 일이 더 중요해집니다.

Draft PR에도 더 쉽게 요청

초안 PR의 reviewer picker에서 Copilot을 바로 요청할 수 있게 UI도 다듬었습니다. 공개 전 첫 검토를 받는 흐름이 짧아졌습니다.

03 Dev 선정 이유: 오픈 모델 핵심 발표

GLM-5.2, 100만 토큰 문맥으로 ‘오래 일하는 모델’을 겨냥한다

Z.ai의 새 플래그십 GLM-5.2는 단순히 입력창을 키우는 대신 대규모 구현, 자동화 연구, 성능 최적화, 복잡한 디버깅처럼 긴 에이전트 궤적을 안정적으로 이어가는 데 초점을 맞췄습니다. 오픈 웨이트 모델이 장기 실행 코딩 경쟁의 한가운데로 들어왔다는 점이 이번 발표의 핵심입니다.

100만 토큰 문맥

MIT 오픈 웨이트

노력 수준을 선택

High와 Max 등 사고 노력 수준으로 성능·지연·비용을 조절할 수 있습니다. Coding Plan에서는 Claude Code, ZCode, OpenCode 같은 코딩 에이전트에 연결할 수 있습니다.

벤치마크는 조건과 함께

공개 발표는 장기 코딩 벤치마크에서 강한 결과를 제시하지만 제공사 측 평가입니다. 실제 도입에서는 작업별 반복 실행, 100만 토큰의 서빙 자원, 피크 시간대 쿼터 비용을 함께 확인해야 합니다.
