AI가 말하고, 움직이고,
더 싸게 일하기 시작한 주

이번 주의 핵심은 새 모델의 개수보다 사용면의 확장입니다. 생성물 표시 의무가 실제 적용되고, 로봇은 전신과 팀워크를 배우며, 음성과 개발 에이전트는 더 자연스럽고 조절 가능한 도구로 내려왔습니다.

This Week in 4 Lines

  1. EU에서는 8월 2일부터 사람과 대화하는 AI와 생성·조작 콘텐츠의 표시 의무가 적용되기 시작했습니다.
  2. Gemini Robotics 2는 휴머노이드 전신 제어와 여러 로봇의 협업을 하나의 지능 계층으로 묶었습니다.
  3. GPT-Live는 듣기와 말하기를 동시에 처리하고, GPT-5.6은 대량 작업 비용과 빠른 처리의 선택지를 넓혔습니다.
  4. 연구자 지원, 여러 저장소 리뷰, 댓글 자동화, Terraform까지 AI가 실제 업무 운영면으로 더 깊이 들어왔습니다.

Editorial Note

이번 주는 거대한 모델 발표보다 AI를 어디에 붙이고 어떻게 통제할지가 더 선명해졌습니다. 표시 의무, 속도와 비용 선택, 접근 권한, 읽기 전용 도구 호출처럼 화려하지 않은 운영 조건이 제품의 실용성을 결정하기 시작했습니다.

01 Icebreaker 선정 이유: 생성물 신뢰 기준

EU AI 표시 의무, “AI가 만들었다”를 보이게 하는 단계로

EU AI Act 제50조의 투명성 의무가 8월 2일부터 적용되기 시작했습니다. 이제 AI와 대화 중인지, 콘텐츠가 생성되거나 조작됐는지를 사용자가 알아볼 수 있게 설계하는 일이 제품 기능이자 운영 책임이 됩니다.

AI와 대화 중임을 먼저 알림

대화형 AI 제공자는 사용자가 사람 대신 AI 시스템과 직접 상호작용하고 있다는 사실을 알 수 있게 해야 합니다.

기계가 읽는 생성물 표식

AI가 만든 이미지·음성·영상·텍스트를 탐지할 수 있도록 적용 대상 콘텐츠에 기계 판독 가능한 표시를 넣어야 합니다.

딥페이크는 공개가 원칙

딥페이크를 배포하는 쪽도 사람이 AI 생성·조작물임을 알아볼 수 있게 공개해야 합니다.

공익 정보는 편집 책임까지

사람의 검토나 편집 통제 없이 만든 공익 사안의 텍스트도 AI 생성 사실을 밝혀야 합니다. 단순 워터마크를 넘어 편집 과정이 중요해졌습니다.

02 Main 선정 이유: 물리 세계 에이전트

Gemini Robotics 2, 손만 쓰던 로봇이 걷고 협업한다

Google DeepMind는 시각과 언어를 행동으로 바꾸는 Gemini Robotics 2 계열을 공개했습니다. 테이블 위 조작을 넘어 휴머노이드의 전신 이동, 정교한 손동작, 여러 로봇의 역할 분담까지 하나의 작업 흐름으로 이어집니다.

발끝부터 손끝까지 제어

휴머노이드가 걷고, 몸을 낮추고, 물건을 집어 선반에 넣는 전신 작업을 하나의 모델 체크포인트로 수행합니다.

수백 번 판단하는 장기 작업

ER 2는 몇 분 동안 이어지는 작업을 계획하고 진행 상황을 추적하며, 실패한 단계를 고쳐 다시 시도하도록 설계됐습니다.

로봇끼리 역할을 나눔

서로 다른 로봇이 소통하며 한 대로는 어려운 작업을 함께 처리합니다. 소프트웨어의 다중 에이전트 구조가 물리 환경으로 옮겨간 셈입니다.

공개 범위는 모델마다 다름

ER 2는 Google AI Studio에서 쓸 수 있지만 VLA와 온디바이스 모델은 얼리 액세스 파트너 대상입니다. 손가락 조작과 이동 속도도 아직 도전 과제로 남았습니다.

02 Main 선정 이유: 대화 지연의 구조 변화

GPT-Live, 말을 끊어 듣는 대신 듣고 말하기를 동시에

OpenAI는 3세대 음성 시스템 GPT-Live의 구조를 공개했습니다. 사용자의 말이 끝났는지 작은 모델이 먼저 판정하던 단계를 없애고, 음성 모델이 계속 들으면서 동시에 말하는 방식으로 바꿨습니다.

듣기와 말하기를 동시에

풀듀플렉스 구조라 사용자가 끼어들거나 잠시 멈춰도 별도 턴 감지기의 결정을 기다리지 않습니다.

말의 빠른 길과 도구의 느린 길 분리

음성은 전용 경로로 계속 흐르고, 깊은 추론과 도구 호출은 비동기로 처리해 느린 작업이 대화를 멈추지 않게 했습니다.

필요할 때 프런티어 모델에 위임

복잡한 판단이 필요하면 GPT-5.5 같은 모델에 맡기되 음성 흐름은 유지합니다. 한 모델이 모든 일을 떠안지 않는 구조입니다.

목소리가 앱 조작으로 이어짐

이 기반은 ChatGPT 데스크톱 앱에서 컴퓨터를 제어하고 여러 에이전트를 조율하는 음성 기능에도 쓰입니다.

02 Main 선정 이유: 에이전트 운영비 재계산

GPT-5.6 가격 재편, 싸게 많이 돌리거나 빠르게 끝내거나

OpenAI는 7월 30일 GPT-5.6 Luna 가격을 80%, Terra 가격을 20% 낮추고 Priority Processing을 Fast mode로 바꿨습니다. 같은 모델군에서도 작업량과 지연시간에 따라 비용 전략을 나누라는 신호입니다.

Luna 입력 0.20달러, 출력 1.20달러

100만 토큰 기준 새 가격입니다. 분류, 추출, 다수 하위 에이전트처럼 반복량이 큰 작업의 비용 문턱이 크게 내려갔습니다.

Terra 입력 2달러, 출력 12달러

일상적인 코딩과 업무 자동화에 쓰는 중간급 모델도 20% 낮아졌습니다. 기존 예산으로 더 많은 재시도와 검증을 넣을 여지가 생깁니다.

Sol Fast는 최대 2.5배 속도

지능은 그대로 두고 표준 처리의 두 배 가격으로 응답 속도를 높입니다. 실시간 지원이나 짧은 배치 창처럼 시간이 더 비싼 업무에 맞습니다.

토큰값보다 성공 비용

싼 모델의 반복 수정과 사람 검토까지 포함하면 더 강한 모델이 오히려 경제적일 수 있습니다. 모델 단가가 아니라 완료까지의 총비용을 봐야 합니다.

02 Main 선정 이유: 연구 접근성 확대

ChatGPT for Academic Researchers, 10만 연구자에게 프런티어 도구

OpenAI는 선정된 대학의 과학자·수학자·엔지니어 10만 명에게 프런티어 모델과 연구 도구를 무료 제공하는 프로그램을 시작했습니다. 올여름 1만 명으로 출발해 2027년까지 확대합니다.

GPT-5.6과 Codex를 무료로

GPT-5.6 Sol Pro를 포함한 모델, 더 넓은 컨텍스트, 확대된 딥리서치와 Codex 작업 환경을 제공합니다.

연구자 한 명이 동료 네 명을 초대

승인된 참여자는 같은 기관의 협업자 최대 4명을 부를 수 있습니다. 개인 채팅보다 연구팀 단위 사용을 염두에 둔 구조입니다.

75개 이상 생명과학 스킬

유전체, 단일세포 분석, 단백질 모델링, 약물 발견을 위한 스킬과 문헌·데이터베이스·노트북 커넥터를 묶습니다.

선정 기관·소속 검증이 필요

누구나 즉시 쓰는 무료 플랜은 아닙니다. 연구 활동이 활발한 학위 수여 대학의 소속을 확인하며, 데이터는 기본적으로 모델 학습에 쓰지 않습니다.

03 Dev 선정 이유: 여러 작업면을 한 대화로

ChatGPT 데스크톱, 여러 저장소와 브라우저 맥락을 한곳에

7월 30일 데스크톱 앱 업데이트는 코딩, 웹 탐색, 이미지 편집을 별도 도구가 아니라 하나의 대화에서 이어지는 작업면으로 묶었습니다.

여러 저장소 diff를 한 번에 리뷰

멀티 폴더 프로젝트의 저장소와 변경 라인을 모아 보고, 저장소마다 화면을 바꾸지 않고 하나의 리뷰에서 검사합니다.

방문 기록과 열린 탭이 맥락

내장 브라우저 기록을 검색하고 Chrome 확장으로 열린 탭이나 선택한 문장을 대화에 바로 가져올 수 있습니다.

영상과 웹페이지에서 바로 질문

YouTube 영상에 질문하거나 웹페이지를 우클릭해 Ask ChatGPT를 실행합니다. 복사와 붙여넣기 단계를 줄이는 변화입니다.

이미지별 코멘트로 수정 범위 지정

생성 이미지를 크게 열어 여러 결과에 코멘트를 달고, 선택한 이미지에만 수정 지시를 보낼 수 있습니다.

03 Dev 선정 이유: API 운영의 코드화

OpenAI 공식 Terraform, 모델 호출보다 권한과 한도를 먼저 코드로

OpenAI가 API Platform 리소스를 코드로 관리하는 공식 Terraform provider를 정식 공개했습니다. 모델을 부르는 애플리케이션뿐 아니라 프로젝트, 권한, 서비스 계정, 사용 한도까지 변경 이력과 검토 절차 안에 넣을 수 있습니다.

프로젝트·사용자·그룹을 선언

조직과 프로젝트 구성을 콘솔에서 반복 클릭하는 대신 설정 파일로 정의하고 같은 구조를 재현합니다.

역할과 서비스 계정도 변경 검토

역할, 접근 할당, 서비스 계정, 인증서, 초대를 코드 리뷰와 승인 흐름에 포함할 수 있습니다.

레이트리밋과 드리프트까지 관리

프로젝트별 호출 한도를 정의하고, 실제 환경이 선언한 구성과 달라졌는지 찾아 다시 맞출 수 있습니다.

관리자 키의 보관이 전제

Terraform 1.0 이상과 OpenAI Admin API 키가 필요합니다. 자동화가 쉬워진 만큼 키 노출 방지와 최소 권한이 먼저입니다.

03 Dev 선정 이유: 트리거와 비용 손잡이

Copilot 자동화, 댓글로 깨우고 추론량까지 고른다

GitHub Copilot cloud agent는 이제 이슈나 PR 댓글을 조건으로 자동 작업을 시작하고, 작업을 맡길 때 모델의 추론 수준도 선택할 수 있습니다. 자동화의 시작점과 비용을 사람이 더 구체적으로 통제하게 됐습니다.

특정 댓글이 실행 버튼

이슈나 PR에 지정한 문장이 달리면 cloud agent 자동화를 시작합니다. 별도 화면으로 이동하지 않고 협업 흐름 안에서 호출합니다.

문서화·오류 조사·후속 이슈

PR 변경에 맞춘 문서 갱신, 스택 트레이스 조사, 리팩터링 후속 이슈 생성이 공식 예시로 제시됐습니다.

복잡하면 추론을 높이고 크레딧도 증가

지원 모델은 실행 전에 추론 수준을 선택합니다. 높은 단계는 복잡한 문제에 유리할 수 있지만 토큰과 AI 크레딧을 더 씁니다.

유료 플랜과 관리자 정책 필요

Copilot Pro 이상에서 제공하며 Business와 Enterprise는 관리자가 cloud agent 정책을 켜야 합니다.

이번 주 연구 노트: 에이전트를 어떻게 더 안전하고 값싸게 믿을까

이번 주 논문은 도구 설명 형식, 여러 모델의 협업, 다회차 대화, 실제 추천 시스템, 출신 라벨이 안전성과 성과 평가를 어떻게 흔드는지 살폈습니다. 아래 수치는 모두 각 논문 저자의 보고입니다.

SafeKeep: 도구 스키마가 거부 신호를 약하게 만든다

26명 대학생의 206개 평가 보고에서 목표 작업 실패율은 23.1%였고, 다회차 대화는 단일 회차보다 2.5배 자주 실패했습니다. 만족도만으로 성공을 판단하기 어렵습니다. arXiv

SnapLGR: 생성형 검색을 실제 추천에 배포

Snapchat 짧은 영상 추천에 LLM 기반 생성형 검색을 적용했습니다. 라이브 A/B 테스트에서 시청 시간 0.37% 증가를 보고해 작은 개선도 대규모 서비스에서는 의미가 있음을 보여줍니다. arXiv
